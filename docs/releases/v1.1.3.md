# v1.1.3 release notes

Patch release: a phone loads a new deploy by itself instead of waiting for a tap on "bordr has updated".

## Changes

- Load a new build without the tap when nothing would be lost. The app already noticed a new deploy within 30 seconds and showed "bordr has updated · tap to reload"; it now reloads on its own once the page is in the background, or has been untouched for a minute. Composer drafts and unacknowledged sends already survive a reload, so the pill only stays while a reload could still lose something: a dictation still listening, photos picked but not sent, a request in flight, a focused field that nothing saves, or a transcript scrolled back through history. If a page is still stale straight after reloading itself, it keeps the pill for five minutes rather than reloading again, so a broken deploy cannot loop (#81).

## Upgrading

No configuration changes. Pull, then `bun run deploy`.

A phone running v1.1.2 or earlier still shows the pill once for this update; after that tap, later deploys load by themselves.
