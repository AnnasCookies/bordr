# v1.2.0 release notes

Minor release: bordr runs on herdr-core, the runtime under the herdr desktop app, as well as on the TUI herdr. Code gets a copy button, and an answered question is confirmed as soon as the screen shows it landed.

## Changes

- Run on herdr-core (`hc`) as well as the TUI herdr. bordr picks the backend from the socket's path; `HERDR_BACKEND=core|tui` overrides it, and with both running it stays on the TUI and says so in its log. Machines core links (`hc machine add`) show up as bordr machines, reached through core. Rename, focus, split, swap, zoom, new tabs and worktrees are hidden on core, where the layout belongs to herdr-app (#87).
- Every harness works on herdr-core as it does on the TUI. codex, grok, agy and copilot show their chat rather than the raw screen, agents start through your login shell so their keys and `PATH` are found, and a prompt is never typed into an open dialog. `deploy/install-system-units.sh` takes `--backend tui|core` and installs no herdr unit on core (#90).
- Copy button on fenced code blocks and command blocks. It keeps line breaks, works over plain http as well as https, and says Copied or Failed. The two sides of an edit diff get no button, since they carry `+` and `-` (#89).
- While the draft is a `!` shell line the composer turns off autocapitalise, autocorrect and spellcheck, so a phone keyboard stops turning `! git` into `! Git` (#89).
- An answer is confirmed when the screen shows it landed, not after a flat half second, and a slow redraw is given up to two seconds instead of coming back "could not confirm" with the card still up. Each answer inside a multi-question ask is confirmed, and a checkbox tick is confirmed as its box fills (#88).
- Claude Code sub-agents that hand their report back, and sub-agents of sub-agents, stop showing as running once they finish. The summary Claude Code writes after compacting collapses to one line again (#86).
- A prompt that starts with a number is no longer taken for a question when the harness echoes it, which left a session stuck on "waiting on you". The terminal preview stays pinned to the live bottom (#85).
- Move to SvelteKit 3 and the official Bun adapter, and take the in-range security patches for DOMPurify, devalue and Vite that `bun audit` reported (#83, #84).

## Upgrading

Pull, `bun install`, then `bun run deploy`.

Installed units need one more step: re-run `deploy/install-system-units.sh` so the unit sets `CONNECTION_IDLE_TIMEOUT`, the official adapter's name for the idle timeout. The old `IDLE_TIMEOUT` is kept in the unit so a rollback to v1.1.3 still works. On a host with both herdrs installed, pass `--backend tui` or `--backend core`.

Nothing changes for a TUI herdr set-up that sets `HERDR_SOCKET`. To move to herdr-core, see step 2 of [the quickstart by hand](../../README.md#by-hand).

## Verification and limits

Each change passed lint, the type check, the unit suite and a production build before it merged. #86, #88 and #89 were each reviewed independently three times over, and what the reviews found was fixed and reviewed again before merging. The copy button and the `!` keyboard settings are covered by the mocked browser suite, which runs in Chromium. The answer wait was run against a real TUI herdr with a dialog herdr does not flag as blocked: four of four answers confirmed.

Not checked:

- The copy button's plain-http fallback on iOS Safari.
- Whether iOS applies the `!` keyboard settings to a field that already has focus. If it does not, they take effect the next time the composer is focused.
- The answer wait's timing on a dialog herdr does flag (Claude Code's) after the review changes. Its logic is unit tested; the 166 ms figure in #88 was measured before them.
