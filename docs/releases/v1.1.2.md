# v1.1.2 release notes

Patch release: messages sent mid-turn no longer show twice, and `bun run deploy` smoke-tests private Unix-socket installs correctly.

## Changes

- Stop messages appearing twice. A sent message shows straight away as a pending bubble and is retired once the agent's transcript records it. The bubble carried the phone's time and the transcript the host's, so a phone running even a second ahead never matched and showed every mid-turn message twice until the agent went idle. The prompt and image routes now return their receipt time (`at`) and the composer re-stamps the bubble with it (#77, regression test in #79).
- Make `bun run deploy` smoke-test the address the service actually serves. `package.json` passed `${BORDR_URL:-http://127.0.0.1:7682/}` to `scripts/smoke.ts`, and the script shell never reads `.env`, so the loopback default always overrode `BORDR_URL` and every `SOCKET_PATH` deploy reported `ERR_CONNECTION_REFUSED` after a successful restart. `scripts/smoke.ts` now reads `BORDR_URL` itself (#78).
- With no `BORDR_URL`, `scripts/smoke.ts` reaches the installed unit's `SOCKET_PATH` through a short-lived loopback forwarder. It admits only connections whose first request carries a random per-run token held in the smoke process's memory, so it never extends the socket's file-permission boundary to other local users (#79).
- Record the demo video at the 402×800 viewport so `demo.mp4` and `demo.gif` are no longer cropped (#76).

## Upgrading

No configuration changes. Pull, then `bun run deploy`. Setting `BORDR_URL` to the HTTPS address printed by `tailscale serve` remains the recommended smoke target, since it also exercises the Tailscale proxy.

Phones pick up the new composer on their next page load; an installed PWA revalidates its shell automatically.
