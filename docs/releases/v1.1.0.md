# v1.1.0 release notes

Prepared for the next release. The v1.1.0 tag and release have not been published.

## Changes

- Show workflow runs and their agents, remote workspace labels and nested worktrees.
- Require recorded evidence before showing a child or workflow as complete.
- Keep questions, queued confirmations, write-in drafts and read marks bound to their source.
- Keep recalled controls inert until live data arrives; retain recoverable drafts after refused sends.
- Release pane geometry on blur and ignore stale lease responses.
- Allow only resolved regular raster files through the screenshot-folder exception.
- Restrict untrusted Markdown styling and executable raw assets, while retaining safe document links and sandboxed sibling assets.
- Make validated private Unix-socket transport the shipped service-unit default.

## Required upgrade migration

Upgrading the application alone does not migrate an existing TCP deployment.

1. Reinstall the appropriate canonical service unit. System units are recommended for a host that must remain available after logout.
2. Change the Tailscale Serve target from TCP to Bordr's private Unix socket.
3. Set `BORDR_URL` to the HTTPS address used by the phone.
4. Restart through the chosen service manager, confirm the old TCP listener is absent, and run the browser smoke check against `BORDR_URL`.
5. Reload open clients so they receive the updated application.

See [the canonical installation instructions](../../README.md#keep-it-running) and [the container/loopback boundary](../../SECURITY.md#containers-and-loopback).

**A TCP listener reachable by untrusted containers remains unsafe, even after upgrading.** Do not add a TCP fallback to such a deployment. Existing services and proxy settings were not changed while preparing this release.

## Verification and limits

The merged application tree was checked with full unit/build gates, real Linux private-socket HTTP/no-TCP startup, synthetic desktop/mobile interaction tests and dedicated Chromium/WebKit security tests. Release preparation reruns the repository gates with the new package version and the frozen dependency lockfile.

This does not establish actual macOS/iOS/Docker Desktop or cross-UID runtime acceptance. The dedicated cross-site browser fixture supplies Fetch Metadata to test Bordr's response, not the browser's native local-network policy. The application still has no login; access to the tailnet and to the host remains the trust boundary.
